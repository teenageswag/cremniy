# Plan: Fix Autocomplete Bugs + Add Snippets & Smart Document Words

## Problem Summary
1. **`#` prefix bug**: Typing `#d` → suggestions disappear because `wordUnderCursor()` returns `"d"` but XML stores `"#define"` — prefix match fails
2. **No snippet support**: `reinterpret_cast` should expand to `reinterpret_cast<>()` with cursor inside `<>`
3. **Weak document words**: No type/function signature info — just flat "Document" label

## Fix 1: `#` Prefix Bug

**Root cause**: `isWordCharacter()` excludes `#`, so `wordUnderCursor()` returns `"d"` not `"#d"`. The prefix filter checks if `"#define".startsWith("d")` → false → empty results.

**Fix**: Remove `#` from XML preprocessor entries. Store `include`, `define`, `ifdef` etc. without `#`. The `#` is already typed by the user before the popup appears.

```cpp
void CodeCompleter::onCompletionAccepted(const QString& text) {
    WordInfo word = wordUnderCursor();
    // For preprocessor items, prepend # if the user already typed it

    if (!word.text.isEmpty() && word.startByte > 0) {
        QByteArray buf = m_editor->getBuffer()->read(word.startByte - 1, 1);
        if (buf == "#" && !text.startsWith("#"))
            insertText = "#" + text;
    }
    // ... rest of insertion logic
}
```

## Fix 3: Smart Document Words

Instead of just "Document" category, parse common C++ patterns:

### Function detection
Match patterns like: `returnType functionName(params) {` or `returnType functionName(params);`
- Extract: function name, return type, parameters
- Show as: `functionName` with detail `returnType functionName(params)`

### Variable detection  
Match patterns like: `Type varName = value;` or `Type varName;`
- Extract: variable name, type
- Show as: `varName` with detail `Type varName`

### Implementation in `collectDocumentWords()`

After extracting a word, look at the surrounding context:

```cpp
// After finding a word at position [start, end) in the text:
// Check if it's a function definition
// Look backward for return type pattern
// Look forward for (params) pattern

// Simple heuristic: if word is followed by '(' and we're not in a #include line
// → it's a function call/definition

// If word is preceded by a type keyword (int, void, auto, std::string, etc.)
// → it's a variable declaration
```

### Changes to `collectDocumentWords()`

```cpp
void CodeCompleter::collectDocumentWords()
{
    // ... existing word extraction ...

    for each word found:
        // Look at context around the word
        QString detail;
        int detailPriority = 3;

        // Check if followed by '(' → function
        if (nextNonSpaceChar == '(') {
            // Extract preceding type
            detail = extractReturnType(text, start);
            detailPriority = 2; // Higher priority for functions
        }
        // Check if preceded by a type → variable
        else if (isTypeContext(text, start)) {
            detail = extractVariableType(text, start);
            detailPriority = 2;
        }

        m_documentItems.append({ word, "", detail, "Document", detailPriority });
}
```

For v1, use simple heuristics:
- If word is followed by `(` within 5 chars → function (show `()` suffix)
- If word starts with uppercase and is preceded by space → likely class/type
- Otherwise → generic identifier
