# Plan: Fix # Duplication and Header Suggestions Vanishing

## Root Causes (confirmed by code trace)

### Bug 1: `##define` double `#`
**Location**: `CodeCompleter::onCompletionAccepted()`, line ~582
**Cause**: The `#`-strip guard checks `word.byteLength == 0`, but when user types `#d` and selects `#define`, `wordUnderCursor()` returns `{text="d", byteLength=1}`. Guard is skipped, `replaceRange(1, 1, "#define")` produces `#` + `#define` = `##define`.

### Bug 2: Header suggestions vanish after `#include <i`
**Location**: `CodeCompleter::updateCompletions()` and `triggerCompletion()`, the `isHeaderContext` check
**Cause**: `isHeaderContext` uses `linePrefix.endsWith("<")`. After typing `#include <i`, the line ends with `i`, not `<`, so `isHeaderContext = false`. This triggers `#`-prepend, turning prefix `"i"` into `"#i"` which matches no header item.

## Fix 1: `onCompletionAccepted()` — Fix `#`-strip logic

**File**: `src/libs/CodeEditor/src/widgets/completion/CodeCompleter.cpp`

Replace the `#`-strip guard:

```cpp
// OLD (broken):
if (word.byteLength == 0 && insertText.startsWith("#") && !isHeaderContext) {
    qint64 cursorPos = m_editor->cursorPosition();
    if (cursorPos > 0) {
        QByteArray buf = m_editor->getBuffer()->read(cursorPos - 1, 1);
        if (buf == "#") {
            insertText = insertText.mid(1);
        }
    }
}

// NEW (fixed):
// If replacement text starts with # and there's a # just before the
// replaced range, strip the leading # to avoid ## duplication
if (insertText.startsWith("#") && !isHeaderContext) {
    qint64 checkPos = (word.byteLength > 0) ? word.startByte : m_editor->cursorPosition();
    if (checkPos > 0) {
        QByteArray buf = m_editor->getBuffer()->read(checkPos - 1, 1);
        if (buf == "#") {
            insertText = insertText.mid(1);
        }
    }
}
```

This handles BOTH cases:
- `word.byteLength == 0` (cursor right after `#`)
- `word.byteLength > 0` (user typed `#d` then selected `#define`)

## Fix 2: `updateCompletions()` / `triggerCompletion()` — Fix header context detection

**File**: `src/libs/CodeEditor/src/widgets/completion/CodeCompleter.cpp`

Replace the `isHeaderContext` logic. The simplest correct approach: if the line starts with `#include`, we're in header context regardless of what comes after.

```cpp
// OLD (broken - uses endsWith):
bool isHeaderContext = linePrefix.startsWith("#include")
                       && (linePrefix.endsWith("<") || linePrefix.endsWith("\""));

// NEW (fixed - just check startsWith):
bool isHeaderContext = linePrefix.startsWith("#include")
                       || linePrefix.startsWith("# include");
```

Apply this change in BOTH `triggerCompletion()` and `updateCompletions()`.
